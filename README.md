# 투자주식 회계·세무조정 검토 시스템
> Investment Tax Reconciliation — local prototype (v6)

**회계 계산을 자동화하되, 세무조정의 법적 판단과 최종 반영은 사람이 통제하는 검토 중심 웹앱.**

## 프로젝트 의도

투자주식의 매수·매도·평가를 입력하면 회계상 장부금액과 세법상 취득원가를 계산하고, 회계분류별 손익 인식과 세무조정 후보를 연결합니다. 목표는 '숫자를 대신 계산하는 도구'에 그치지 않고, **어떤 거래와 회계처리가 어떤 세법 규칙으로 어떤 조정에 연결됐는지 설명하고 검증할 수 있는 시스템**입니다.

설계 원칙:
- **자동 계산 ≠ 자동 승인**: 계산 엔진은 조정 *후보*를 제시하고 검토자가 금액·근거·소득처분을 확인해 승인합니다.
- **회계와 세무를 구분**: FVOCI/FVTPL 회계장부는 구분하고, 동일 권리의 동일 종목 세무원가는 통합 풀로 계산합니다.
- **한 거래, 복수 조정**: 회계상 PL·OCI·자본 내 대체, 익금/손금 조정, 유보·△유보·기타를 별도 차원으로 추적합니다.
- **검증 가능성**: 원천 거래 → 계산 → 검증표 → 승인 → 유보원장 → 결산 확정의 근거와 이력을 보존합니다.
- **보수적 통제**: 근거가 부족한 법적 판단은 자동 확정하지 않고 검토 대상으로 표시합니다.

## 현재 구현된 기능

2026-10-26 기준, 계산 검증·연도별 정책·정규화 DB 설계·생성·앱 연결 단계까지 완료했습니다. [완료 현황과 후속 과제](docs/IMPLEMENTATION_STATUS.md)에서 범위와 검증 결과를 확인할 수 있습니다.

|---|---|

| 회계·세무 계산 | 회계상 평가·처분손익, OCI 관련 계산, 세법상 총평균법/이동평균법 시뮬레이션 |
| 세무원가 풀 | 동일 종목 FVOCI/FVTPL 통합 세무원가 계산, 기말 보유수량 기준 배분 및 대사 |
| 사업연도 정책 | 결산월 설정, 사업연도별 원가계산 방법·신고/변경 이력 입력 |
| KRX 가격 조회 | API 키 및 서비스 승인이 있을 때 종가 조회 시도, 가격 저장 전 확인 |

| 자동 검증 | 수량/중복 거래/평가 누락/가격 기준일/일부 분개·장부금액 대사/신고 정책 확인 |
| 서버 독립 재계산 | 저장된 원천을 독립 계산하여 브라우저 금액 비교, 승인 전 자산별 유보 증감 대사, 결산 전 기말 장부 재확인 |
| 세무조정 검증표 | 거래별 초안 생성, 복수 조정 행, 검토 근거와 소득처분 확인 |
| 2026 조정 규칙 | 적용범위 확인 후 PL·OCI·자본 내 대체를 구분한 원인별 행 제안, 법령 출처·시행본·확인일 기록, 승인·결산 시 재검사 |
| 승인 통제 | 승인된 유보·△유보만 원장 전기, 기타는 조정 이력에 보존 |
| 정정 | 승인 취소 시 반대 부호 원장 행과 이력 보존, 새 검증표 재생성·재승인 |
| 결산 통제 | 매도·평가 검증표 승인 및 유보잔액 대사 확인 후 사업연도 확정, 일부 수정 차단 |

**구현됨은 회계·세법상 정합성이 완전히 검증됐다는 뜻이 아닙니다.** FVOCI 부분 처분은 [8개 산술 정답 사례와 원장·결산 대사](docs/FVOCI_RESERVE_RECONCILIATION.md)를 검증했지만, 법적 소득처분·예외까지 확정한 것은 아닙니다.

## 업무 흐름

```text
거래 / 평가 / 회계정책 입력
       ↓
회계장부·통합 세무원가 계산
       ↓
세무조정 후보 + 검증표 자동 생성
       ↓
수량·금액·정책·유보 검증
       ↓
담당자 법령·소득처분·금액 검토
       ↓
승인 → 유보원장 전기 / 기타 조정 이력 보존
       ↓
사업연도 결산 확정 → 차기 이월
```

화면별 입력 순서, 검토 방법, 승인·정정·결산 절차는 [`docs/WORKFLOW.md`](docs/WORKFLOW.md)에서 자세히 설명합니다.

### FVOCI 처리 원칙

- FVOCI 지분상품의 평가손익과 처분 시 누적 OCI는 당기손익과 분리해 관리합니다.
- 처분 시 OCI를 당기손익으로 재분류하지 않습니다.
- **누적 OCI의 이익잉여금 대체 / OCI 유지**를 적용 시작 사업연도·확인자·사유와 함께 저장합니다. 종료연도 기준으로 다음 변경 전까지 적용하며, 기존 공통 정책과 확정 결산은 보존합니다. [연도별 정책·이월 정답표](docs/FVOCI_POLICY_YEARS.md)를 참고하세요.
- OCI에 인식된 금액을 곧바로 '기타'로 확정하지 않습니다. 세무조정 방향·소득처분·유보 환입을 구분하여 검토합니다.

## 실행

### 정규화 DB와 앱 연결

새로 실행할 때 DB 파일이 없으면 **28개 업무 테이블과 관리 테이블**을 생성하고 앱을 연결합니다. 종목·자산·거래·평가·연도별 정책은 각 테이블에서 읽고 저장하며, 서버 계산 → 검증표 → 복수 조정 행 → 승인·취소 → 유보원장 → 결산·이월까지 연결했습니다.

```bash
python3 -m app.database inspect
```

기본 파일은 `data/investment.sqlite3`입니다. 기존 형식의 DB가 있으면 원래 저장 방식을 유지하며 자동 이전·삭제하지 않습니다. 다른 새 파일은 `python3 -m app.database create --path data/new.sqlite3`로 만들고 `INVESTMENT_DB_PATH`로 선택할 수 있습니다. [생성·연결·보존 범위](docs/DATABASE_SETUP.md)를 참고하세요.

### 현재 앱 실행

Python 3 (표준 라이브러리), 최신 브라우저가 필요합니다.

```bash
python3 -m app.server
```

브라우저에서 **http://127.0.0.1:8000/** 접속. HTML 파일을 직접 열면 SQLite 연동이 되지 않습니다.

선택적으로 KRX API 키 설정:

```bash
export KRX_API_KEY='발급받은_키'
python3 -m app.server
```

KRX 시세 조회는 API 이용 승인과 응답 형식에 의존하며, 실제 인증키 기반 통합 검증은 완료하지 못했습니다. 조회한 종가는 실제 체결가와 다를 수 있습니다.

### 데이터 보관

- 로컬 SQLite 파일: `data/investment.sqlite3` (첫 실행 시 생성)
- `INVESTMENT_DB_PATH` 환경변수로 DB 위치 지정 가능
- 기존 브라우저 `localStorage` 데이터는 최초 접속 시 가져오기 여부를 선택할 수 있습니다.
- `data/`, DB 파일, API 키, 실제 고객·거래정보는 Git에 커밋하지 않습니다.
- 단일 사용자 로컬 프로토타입이므로 **외부 네트워크에 공개 배포하지 마세요.**

## 검증 상태와 한계

- **신고용 완성품이 아닙니다.** 일반 내국법인의 국내 상장주식을 중심으로 한 학습·검토용 프로토타입입니다.
- FVOCI 부분 처분 유보 환입은 별도 검산기로 거래별 산술 정답과 승인원장·결산까지 비교합니다. 일반 매수·매도·평가와 일정한 원가정책을 가정한 8개 사례이며, 모든 거래·법적 적정성의 검증을 의미하지 않습니다.
- 브라우저 금액을 서버에서 독립 재계산하여 승인·결산에 연결합니다. 세법 적용·신고기한·예외는 자동 법적 확정하지 않습니다. 기존 검증표 전환 방법은 [서버 재계산 안내](docs/SERVER_RECALCULATION.md)를 참조하세요.
- 2026 복수 행 규칙은 12월 결산·정상 장내거래·종목별 단일 자산 등의 범위를 담당자가 확인해야 켜집니다. 부도 등 감액·특수 거래·혼합 분류는 자동 행을 만들지 않습니다. 기존 미확정 검증표는 규칙 근거를 포함해 취소·재생성·재승인해야 할 수 있으며, 확정 결산을 자동 변경하지 않습니다.
- 실제 K-IFRS 및 법인세 신고 실무에 사용하려면 관련 기준서·법령·사례 검토와 추가 테스트가 필요합니다.
- 현재 단일 사용자 로컬 환경을 전제로 하며 인증·권한·로그 변조 방지는 미구현입니다.

```text
tests/python/      서버·검증·결산·참조 계산기 테스트
tests/js/          공유 계산 모듈 회귀 테스트 (정답 데이터는 tests/fixtures/)
docs/              개발 이력과 설계 문서
scripts/           과거 마이그레이션 등 개발 보조 도구
data/              로컬 SQLite 데이터(실행 시 생성, Git 제외)
```

서버 코드는 Python 패키지로 구성되어 내부 경로를 명시적으로 관리합니다. `frontend/`만 정적 파일로 제공하며, 서버 소스나 `data/`는 웹 경로로 노출하지 않습니다. 폴더 정리 전과 동일하게 기본 데이터베이스는 저장소 루트의 `data/investment.sqlite3`를 사용합니다.

## 개발 방향

이 프로젝트는 회계사의 판단을 대체하려는 도구가 아니라, **반복 계산을 줄이고 사람이 검토해야 할 쟁점을 드러내며, 검토 과정과 결론을 재현 가능하게 만드는 도구**를 지향합니다.
