# 1단계: 회계·세무 계산 정확성 검증 (초기 구현)

## 실행

```bash
python3 -m unittest tests.python.test_engine -v
```

외부 패키지나 KRX API 키가 필요하지 않습니다.

## 구현된 범위

P0 FVOCI 검산은 `fvoci_reference.py`와 `tests/fixtures/fvoci_cases.json`을 사용합니다. `python3 -m unittest tests.python.test_fvoci_answers -v`로 실행하며, 단일 FVOCI 자산 사례를 두 자본 정책에 대해 Decimal로 독립 계산합니다. 이 파일은 테스트 전용입니다. 운영 서버는 별도의 `app/server/calculation.py`로 독립 재계산하고 승인·결산에 연결합니다. [정답표와 가정](../docs/FVOCI_ANSWER_CASES.md), [서버 연결 안내](../docs/SERVER_RECALCULATION.md)를 참조하세요.

- 독립적인 Python Decimal 기반 FVTPL 참조 계산기 (`engine.py`)
- 매수, 처분, 기말 공정가치 평가, 배당 이벤트
- 세무상 이동평균법 및 연도별 총평균법 **시뮬레이션**
- 세무상 장부금액 − 회계상 장부금액으로 정의한 차이/유보잔액
- 회계상 당기손익과 가정한 세무상 손익의 차이 계산
- 5개의 자동 검증 테스트 (`test_engine.py`)

## 중요한 제한과 후속 작업

1. 이 참조 계산기는 웹앱 JavaScript 계산기와 **아직 연결되지 않았습니다**. 별도 검산 기준이며 웹앱 자동 통합 테스트가 아닙니다.
2. FVOCI, 거래비용, 배당채권 인식/원천징수, 수입배당금 익금불산입, 법인세법 신고·변경 절차, 회계분개 생성은 아직 미구현입니다.
3. 일반적인 평가손익 세무상 불인정 및 배당수익 전액 세무상 인정이라는 **단순화 가정**을 사용합니다. 실제 법인세 신고에 바로 사용할 수 없습니다.
4. 총평균법은 한 사업연도의 후속 취득까지 반영하는 연간 소급 계산 예시입니다. 실제 세법상 계산기간, 종목/자산 분류별 통산 범위, 결산일, 취득사유별 예외, 원단위 반올림은 공식 근거를 검증해야 합니다.
5. 기존 웹앱은 종목별 세무방법 선택, FVOCI/FVTPL 자산 ID별 원가풀 계산 구조가 있어 실제 신고정책 및 동일종목 원가통산 범위와 충돌할 수 있습니다. 확정된 규정에 따라 데이터 모델과 UI를 변경해야 합니다.
6. FVOCI 지분상품은 처분 시 누적 OCI를 손익으로 재분류하지 않는 점과, 세무조정/세무상 장부금액 조정의 표시를 별도로 설계해야 합니다.
7. 현재 `engine.py`의 연말 스냅샷은 해당 연도의 **마지막 입력 이벤트 후** 상태이며, 기말평가 이벤트를 명시적으로 입력해야 결산 상태를 뜻합니다.
8. 향후 거래 순서, 분할, 무상증자, 정책변경, 전기 수정, 연말 미평가, 동일종목의 복수 회계분류, 소수점/원단위 반올림 테스트를 추가해야 합니다.

## 검증 성공 기준

- 독립 기준표와 웹앱 출력값 일치
- 회계장부금액/세무상 장부금액/유보잔액의 연도별 대사
- 일부 처분 및 전량 처분 시 대응 차이 해소
- 수정 거래의 후속 사업연도 재계산
- 계산 정책과 근거 법령의 적용 시점 추적
## 원 단위 계산과 기존 검산의 구분

이 폴더의 기존 FVTPL·FVOCI 참조 사례는 과거 계산 가정의 회귀 검증으로 보존합니다. 새 원 단위 정책의 고정 정답과 두 언어 대사는 [원 단위 처리 기준](../docs/ROUNDING_POLICY.md), `tests/fixtures/won_rounding.json`, `tests/python/test_won_rounding.py`를 참고하세요. Python은 Decimal 입력·Fraction 비례배분, JavaScript는 BigInt 분수로 독립 계산합니다.
