# 세무조정 검토 화면

2026-10-27 기준 구현 안내다. 왼쪽 **세무조정 검토**에서 사업연도를 선택한다.

## 검토 순서

1. **원천 자료·적용 기준 확인**: 거래·평가·정책을 확인한다. 2026 국내 상장주식 자동 규칙은 적용범위의 요건과 예외를 읽고 확인자·근거를 저장해야 사용한다.
2. **금액 재계산·오류 확인**: 서버 재계산 및 검증을 실행한다. 오류는 원천을 수정하고 재검증한다. 경고·오류의 처리 근거는 해당 검증 실행에 연결된다. 처리 기록만으로 오류가 해제되지는 않는다.
3. **조정 행 검토·승인**: 현재 자료로 검증표를 생성하고 종목을 선택한다. 종목명·FVOCI/FVTPL·처분/평가와 승인 대기·승인 완료·취소·원천 변경 상태를 확인한다.
4. **유보원장 대사·결산 확정**: 기초·당기 증감·기말과 계산 유보를 비교한다. 필수 검증표 승인과 오류 해소 후 확정자·의견을 입력하여 결산한다. 서버의 최종 대사를 통과해야 확정된다.

## 표에서 조정 행 편집

JSON 입력 대신 대상 자산, 조정 원인, 익금·손금, 소득처분, 금액, 검토 근거를 표에서 편집한다. 조정 원인은 200자까지이며 행 추가·삭제는 최대 20행 범위에서 가능하다. 유보 증감은 유보이면 양수, △유보이면 음수, 그 외는 0으로 계산한다. 금액 입력과 동시에 과세소득 합계·자산별 유보 증감을 서버 후보와 대사한다. 원 단위 적용 전의 과거 금액은 소수 둘째 자리까지 보존한다.

합계 일치는 산술 검사다. 자동 규칙의 원인별 행을 임의로 상계하거나 소득처분을 변경하면 합계가 같아도 서버가 승인을 차단할 수 있다. 적용범위 미확인 건은 자동 행을 만들지 않으며 담당자가 별도 법적 근거를 검토해야 한다.

편집은 승인 시 저장된다. 검토자·10자 이상 의견·명시적 확인이 필요하다. 승인 요청 중 해당 표는 잠기며 중복 제출은 차단한다. 요청 중 다른 연도나 검증표를 열어도 응답은 다른 편집 내용을 덮어쓰지 않는다. 성공 알림에 승인한 사업연도를 표시하며, 이동한 화면의 목록은 새로고침하여 확인한다. 요청 실패 시 현재 편집 내용을 유지한다. 화면 이동·연도 변경·새로고침에서 미승인 편집이 있으면 폐기 여부를 확인한다.

## 금액 계산 과정과 보존

새 검증표는 서버의 동일한 원천 재계산에서 수량, 매각대금, 회계 제거금액, 세무 처분원가, OCI 및 유보 전후 잔액을 설명용 정보로 보관한다. 예를 들어 매각대금 90원 − 세무 처분원가 50원 = 세무 처분손익 40원과 회계 제거금액 70원에 따른 OCI 변동 20원을 구분한다. 이는 승인 권한을 부여하는 계산 근거를 대체하지 않는다.

승인·취소 회차는 실제 승인했던 조정 행을 읽기 전용으로 보여 준다. 기존 확정 결산이나 승인 기록은 다시 작성하지 않는다. 설명 정보가 없는 예전 검증표는 현재 거래로 과거 수치를 재구성하지 않고 안내 문구를 표시한다. 내부 식별값·계산 식별값·법령 상세는 접어서 확인한다.

## 원장 차이와 처리 이력

계산 유보와 승인 원장이 같으면 **일치**, 차이가 현재 미승인 검증표의 자산별 증감과 정확히 같고 누락된 검증표가 없으면 **승인 대기 차이**, 그 외는 **원장 차이 · 원인 확인**으로 표시한다. 승인 대기 차이 표시는 결산 허가를 뜻하지 않는다.

처리 폼은 열었던 검증 실행 ID·사업연도·원천 버전에 고정된다. 재검증·사업연도 변경 때 폼을 닫고, 만료된 저장 동작은 차단한다. 저장 응답이 늦어도 새로 열린 폼은 닫지 않는다.

## 검증 범위

`test_review_model.js`는 정확한 합계·자산별 대사·승인 원문·차이 상태를, `test_review_ui.js`는 실제 UI 함수의 편집·제출·실패 보존·읽기 전용 표시를 검증한다. `test_review_async.js`는 지연 응답을 사용하여 승인 중 연도·검증표 전환, 취소 응답 중 다른 검증표 편집, 후속 조회 중 새 편집, 중복 클릭, 전송 중 편집 차단, 실패 후 복구, 처리 폼과 실행 ID 결합을 검증한다.

Python의 `test_review_presentation.py`는 기존·정규화 DB 양쪽에서 계산 과정 보존, 원 단위 잔여액, 승인 조정 원인 저장과 공백·200/201자 경계를 확인한다. 테스트 자료와 브라우저 예제는 임시 DB에만 사용한다. 실제 KRX 인증 환경과 모든 법령 예외·모바일 조작 전체를 검증한 것은 아니다.
