# 투자자산 세무조정 업무 워크플로우

이 문서는 프로그램을 처음 사용하는 사람이 **어떤 순서로 자료를 입력하고, 무엇을 검토한 뒤, 언제 결산을 확정해야 하는지** 이해할 수 있도록 정리한 사용 안내서입니다.

이 프로그램은 회계·세무 계산과 검토 자료 작성을 돕는 도구입니다. 계산 결과가 곧바로 세법상 확정 결론이 되는 것은 아니며, 최종 세무조정 방향과 소득처분은 담당자가 근거를 확인한 뒤 승인해야 합니다.

## 전체 흐름 한눈에 보기

```text
1. 회사·사업연도 정책 설정
             ↓
2. 종목과 투자자산 등록
             ↓
3. 매수·매도·배당 입력
             ↓
4. 결산일 공정가치 평가 입력
             ↓
5. 회계장부와 세무원가 자동 계산
             ↓
6. 자동 검증 실행 및 오류 수정
             ↓
7. 세무조정 검증표 생성
             ↓
8. 담당자 검토·승인
             ↓
9. 유보원장 대사 및 결산 확정
             ↓
10. 다음 사업연도로 이월
```

## 0. 시작 전 준비

저장소 폴더에서 다음 명령으로 프로그램을 실행합니다.

```bash
python3 -m app.server
```

브라우저에서 `http://127.0.0.1:8000/`에 접속합니다. HTML 파일을 직접 열면 SQLite 데이터베이스와 검증·승인 기능이 연결되지 않습니다.

업무 데이터는 기본적으로 `data/investment.sqlite3`에 저장됩니다. 실제 자료를 입력하기 전과 결산 확정 전에는 이 파일을 별도로 백업하는 것이 좋습니다.

## 1. 회사·사업연도 정책 설정

먼저 **데이터 관리** 화면에서 회사에 적용할 기본 정책을 입력합니다.

- 결산월
- 세무상 원가계산 방법
- 적용 사업연도
- 신고 여부와 신고일
- 계산 방법 변경 여부
- 신고서 접수번호나 검토 근거

같은 화면의 **FVOCI 누적 OCI 처분 정책 · 사업연도별 관리**에서 적용 시작 사업연도와 대체/유지 선택, 확인자·사유를 저장합니다. 해당 연도부터 다음 변경 전까지의 처분에 적용하며 과거 확정 결산은 보존합니다. 예전에 처분해 유지한 OCI를 새 대체 정책으로 자동 이동하지는 않습니다. [연도별 정책과 이월 예시](FVOCI_POLICY_YEARS.md), [기본 FVOCI 정답표](FVOCI_ANSWER_CASES.md)를 참고하세요.

결산월은 거래가 어느 사업연도에 포함되는지를 결정합니다. 예를 들어 3월 결산 법인은 2026년 4월 1일부터 2027년 3월 31일까지의 거래가 2027사업연도에 포함됩니다.

정책을 화면에 입력했다는 이유만으로 세법상 신고 또는 변경 절차가 유효해지는 것은 아닙니다. 신고서와 관련 증빙을 별도로 확인해야 합니다.

## 2. 종목과 투자자산 등록

**종목 마스터**에서 종목코드와 종목명을 등록한 뒤, **투자자산** 화면에서 실제 관리 대상을 만듭니다.

같은 종목이라도 회계 분류가 다르면 투자자산을 나누어 등록할 수 있습니다.

- `FVOCI`: 평가손익을 기타포괄손익으로 인식하는 자산
- `FVTPL`: 평가손익을 당기손익으로 인식하는 자산

회계장부는 FVOCI와 FVTPL을 구분하지만, 동일 종목·동일 권리의 세무상 취득원가는 종목별 통합 원가 풀로 계산됩니다. 따라서 종목코드는 정확히 입력해야 합니다.

## 3. 매수·매도·배당 입력

**매수·매도·배당** 화면에서 거래를 순서대로 입력합니다.

### 매수

- 거래일
- 수량
- 실제 취득금액 또는 단가
- 필요한 경우 거래 관련 메모

### 매도

- 거래일
- 수량
- 실제 처분금액 또는 단가
- 회계상 원가 계산에 필요한 정보

보유수량보다 많이 매도하거나 같은 거래를 중복 입력하면 자동 검증에서 오류로 표시됩니다.

### 배당

- 배당 인식일
- 배당금액
- 관련 자산

현재 계산은 배당수익 전액을 단순하게 처리하며, 수입배당금 익금불산입 등 개별 세법 적용은 별도로 검토해야 합니다.

KRX 종가 조회 기능은 입력을 돕는 참고 기능입니다. 조회된 종가는 실제 체결가격이나 거래 증빙을 대신하지 않으므로 반드시 원래 자료와 비교한 뒤 저장합니다.

## 4. 결산일 공정가치 평가 입력

**공정가치 평가** 화면에서 사업연도 말 현재 보유 중인 자산의 평가자료를 입력합니다.

- 평가일
- 평가수량
- 주당 공정가치
- 가격 기준일
- 가격 출처와 검토 메모

휴장일 때문에 직전 거래일 종가를 사용했다면 평가일과 실제 가격 기준일을 구분해 기록합니다. 보유 중인 자산의 기말평가가 누락되거나 가격 기준일이 지나치게 오래된 경우 자동 검증에서 경고 또는 오류가 발생할 수 있습니다.

## 5. 자동 계산 결과 확인

거래와 평가를 입력하면 프로그램이 다음 내용을 계산합니다.

- 회계상 기말 장부금액
- 회계상 처분손익 또는 평가손익
- FVOCI의 OCI 변동과 자본 내 대체 후보
- 종목별 통합 세무원가
- 세무상 처분손익
- 회계와 세무의 차이
- 세무조정 및 유보 증감 후보

이 단계의 금액은 **검토 대상 초안**입니다. 특히 FVOCI 부분 처분, 유보 환입, 법적 소득처분은 자동 계산값만으로 확정하지 않습니다.

## 6. 자동 검증 실행

**자동 검증** 화면에서 대상 사업연도를 선택하고 검증을 실행합니다.

검증에서는 주로 다음 사항을 확인합니다.

- 보유수량보다 많은 매도 여부
- 중복 거래 가능성
- 결산일 평가 누락
- 가격 기준일 오류 또는 오래된 가격
- 화면 계산 수량과 원천 거래 수량의 일치
- 회계장부금액·세무장부금액·유보잔액의 대사
- 종목별 통합 세무원가와 분류별 배분금액의 일치
- 원가계산 정책의 신고·변경 상태
- 일부 회계분개의 차변·대변 일치

검증 결과는 다음과 같이 처리합니다.

- `ERROR`: 원천 자료나 계산 대사가 맞지 않는 상태입니다. 결산 전에 수정해야 합니다.
- `WARNING`: 자동으로 결론 내릴 수 없거나 담당자 확인이 필요한 상태입니다. 근거를 확인하고 검토 결과를 남깁니다.

자료를 수정했다면 검증을 다시 실행해야 합니다. 과거 검증 결과는 이력으로 남고, 새 결과가 이전 결과를 덮어쓰지 않습니다.

## 7. 세무조정 검증표 생성

2026년 일반 내국법인의 국내 상장 보통주라면, 검증표 화면에서 **2026 국내 상장주식 조정 규칙 적용범위**를 먼저 읽습니다. 적용요건과 예외 제외를 확인한 뒤 확인자·근거를 저장해야 원인별 조정 행이 제안됩니다. 자동 승인은 아니며, 혼합 분류·감액 예외 등은 이번 규칙에서 제외됩니다. [정답표와 법령 근거](TAX_ADJUSTMENT_RULES_2026.md)를 참고하세요.

자동 검증 후 **세무조정 검증표**를 생성합니다. 검증표는 매도와 평가 등 원천 자료별로 만들어지며 다음 내용을 보여줍니다.

- 연결된 거래 또는 평가 자료
- 회계상 손익
- 세무상 손익
- OCI 변동
- 이익잉여금 대체액 (처분손익과 구분)
- 원인별 조정 행과 적용 규칙·조문·시행본·확인일
- 세무조정 후보금액
- 유보 발생·환입 후보
- 자동 점검 결과

검증표를 만든 뒤 원천 거래를 수정하면 기존 검증표는 그대로 승인할 수 없습니다. 자료를 다시 검증하고 새 검증표를 생성해야 합니다.

검증표의 금액은 서버가 저장된 자료로 독립 재계산합니다. 혼합 보유의 원가 배분으로 장부 차이가 바뀌는 매수도 생성 대상입니다. 화면의 자산별 배분효과를 확인하고 각 조정 행의 대상 자산을 지정합니다. 승인·결산 단계에서 다시 대사하며, 기존 검증표의 전환 순서는 [서버 재계산 안내](SERVER_RECALCULATION.md)를 참조하세요.

## 8. 담당자 검토와 승인

담당자는 검증표마다 다음 항목을 직접 확인합니다.

1. 조정 방향이 맞는가
   - 익금산입
   - 손금산입
   - 익금불산입
   - 손금불산입
2. 소득처분이 맞는가
   - 유보
   - △유보
   - 기타 등
3. 조정금액과 유보 증감액이 일치하는가
4. 적용 법령, 회계정책, 신고 근거가 있는가
5. FVOCI 처분 시 OCI와 유보 환입을 서로 혼동하지 않았는가
6. 이익잉여금 대체를 새로운 과세손익으로 중복 조정하지 않았는가

승인·결산 시 과세소득 증감 합계와 유보 방향·부호도 검사합니다. 2026 규칙을 적용한 건은 원인별 행을 임의로 상계하거나 소득처분을 바꾸면 차단됩니다. 적용범위를 확인하지 않은 건은 일반 잔액 차이만으로 `기타` 행을 자동 제안하지 않습니다.

검토자 이름, 검토 의견, 적용 근거를 입력한 뒤 승인합니다.

승인 효과는 소득처분에 따라 다릅니다.

- `유보`와 `△유보`: 승인된 금액만 유보원장에 전기됩니다.
- `기타` 등 유보 외 처분: 검증표 승인 이력에는 남지만 유보원장에는 전기되지 않습니다.

## 9. 유보원장 대사와 결산 확정

결산 확정 전에는 다음 조건을 모두 확인합니다.

- 자동 검증의 오류가 모두 해결되었는가
- 남아 있는 경고를 검토하고 승인 여부를 기록했는가
- 해당 사업연도의 매도·평가 검증표가 모두 작성되었는가
- 모든 검증표가 승인되었는가
- 승인된 검증표가 현재 원천 자료와 같은 버전을 기준으로 하는가
- 모든 자산의 기말 수량이 거래내역과 일치하는가
- 세무장부금액에서 회계장부금액을 뺀 차이가 유보원장 잔액과 일치하는가
- 동일 종목의 분류별 세무원가 합계가 종목별 통합 세무원가와 일치하는가

조건이 충족되면 검토자와 결산 메모를 입력하고 사업연도를 확정합니다. 확정된 기말 유보잔액은 다음 사업연도의 기초잔액으로 연결됩니다.

결산 확정 후에는 해당 사업연도의 거래·평가·정책을 일반 방식으로 수정할 수 없습니다. 현재 별도의 결산 재개방 절차는 완성되어 있지 않으므로 확정 전에 백업과 최종 검토가 필요합니다.

## 10. 잘못 승인했을 때의 정정 절차

결산 확정 전 승인 오류를 발견했다면 다음 순서로 처리합니다.

```text
기존 승인 취소
      ↓
기존 유보전기의 반대 부호 정정분 자동 기록
      ↓
원천 자료 또는 검토 내용 수정
      ↓
검증 재실행
      ↓
새 검증표 생성
      ↓
재검토·재승인
```

기존 승인과 유보원장 기록은 삭제하지 않습니다. 취소 이력과 반대 부호 전기를 남겨 무엇이 언제 정정되었는지 추적할 수 있게 합니다.

결산 확정 후 발견된 오류는 프로그램에서 바로 취소할 수 없습니다. 별도의 재개방 정책과 회계·세무 검토가 필요합니다.

- [ ] 최종 검토 후 사업연도를 확정했다.

## 중요한 한계

이 프로그램은 신고용 완성품이 아니라 검토용 프로토타입입니다. 실제 신고에 사용하려면 관련 K-IFRS, 법인세법, 시행령·시행규칙, 유권해석, 회사별 회계정책과 신고 이력을 추가로 확인해야 합니다. 자동 계산과 자동 검증은 전문가의 판단을 대신하지 않습니다.
