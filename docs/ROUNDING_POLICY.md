# 금액 정밀도·원 단위 반올림 기준

상태: **구현·정답표·JavaScript/Python 대사·승인·결산 테스트 완료** · 기준일: 2026-10-26

사용자가 선택한 계산 기준은 **소수 첫째 자리에서 반올림하여 원 단위로 확정·표시**하는 것이다. 평균단가를 먼저 반올림하지 않는다. 계산 정책의 이름은 `KRW_WON_V1`이며 법정 신고서별 절사·출력 단위까지 확정한 것은 아니다.

## 1. 무엇을 언제 반올림하나

| 대상 | 적용 기준 |
|---|---|
| 입력 원문·단가 | 원문 정밀도를 보존. 주당 단가를 먼저 원 단위로 만들지 않음 |
| 매수·매도·배당 총액 | 해당 거래 총액을 한 번 원 단위 반올림하여 계산에 사용 |
| 평가금액 | 보유수량 × 적용 단가를 정확하게 계산한 뒤 총액을 원 단위 반올림 |
| 평균단가 | 확정 취득 총액 ÷ 수량을 정확한 분수로 유지. 소수 자릿수 제한으로 미리 잘라내지 않음 |
| 부분 처분의 원가 | 정밀 평균·비율로 구한 처분 대상 원가를 원 단위 반올림. 반올림한 원가로 평균단가를 매번 다시 만들지 않음 |
| 마지막 처분 | 남은 확정 장부금액·종목 세무원가 전액 제거. 남은 금액이 음수가 되도록 초과 배분하지 않음 |
| 자산 간 세무원가 배분 | 수량 비례로 원 단위 배분, 마지막 보유 자산에 잔여액 반영. 0주 자산에 배분하지 않고 작은 총액의 초과 배분도 제한 |
| 손익·유보·OCI | 위에서 확정한 금액을 연결해 계산. 유보 = 세무원가 − 회계장부, OCI = 보유분 + 처분 후 유지분 |
| 승인 조정 행·원장 | 정수 원만 허용. 과세소득·유보 합계가 맞아도 소수 금액으로 쪼갠 행은 승인하지 않음 |
| 화면 | 금액을 원 단위로 표시. 기존 자료의 표시를 바꿔도 저장된 과거 확정 금액을 덮어쓰지 않음 |

정확히 절반이면 부호와 관계없이 절댓값이 커지는 쪽으로 반올림한다.

| 원래 금액 | 결과 |
|---:|---:|
| 100.49 | 100원 |
| 100.50 | 101원 |
| −100.49 | −100원 |
| −100.50 | −101원 |
| 0.50 | 1원 |
| −0.50 | −1원 |

## 2. 손계산 정답표

### 100원에 산 3주를 1주씩 처분

정밀 평균단가는 `100/3`원이다. 33원으로 바꾼 평균단가를 다음 계산에 사용하지 않는다.

| 처분 | 확정 처분원가 | 남은 확정 원가 |
|---|---:|---:|
| 첫 1주 | 33원 | 67원 |
| 다음 1주 | 33원 | 34원 |
| 마지막 1주 | 34원 | 0원 |

처분원가 합계는 최초 원가 100원과 같다. 마지막 34원은 별도의 기타 손익이나 가짜 유보 조정 행으로 만들지 않는다.

### 아주 작은 금액·평가·큰 금액

| 사례 | 정답 |
|---|---|
| 1원에 산 2주를 1주씩 처분 | 원가 1원·0원, 잔액 0원 |
| 2원에 산 4주를 1주씩 처분 | 원가 1원·1원·0원·0원. 남은 원가보다 많이 제거하지 않음 |
| 보유 3주 × 평가 단가 0.49원 | 총액 1.47원을 반올림해 1원. 단가부터 0원으로 바꾸지 않음 |
| 10조 원 매수만 입력 | JavaScript와 Python 모두 장부·세무원가 10조 원. 이전 EPSILON 보정의 0.02원·0.04원 오차 제거 |
| 10조 원에 산 3주를 1주씩 처분 | 원가 3,333,333,333,333원·3,333,333,333,333원·3,333,333,333,334원 |

FVOCI 3주를 100원에 취득하고 120원으로 평가한 뒤 1주씩 50원에 처분하면 세무 처분원가는 33원·33원·34원이다. 세무 처분손익 합계는 50원이고, 대체 정책에서는 대체액 합계 50원·최종 OCI 0원, 유지 정책에서는 최종 OCI 50원이다. 누적 OCI를 당기손익으로 재분류하지 않는다.

## 3. 총평균법·이동평균법과 연도 경계

총평균법의 평균단가는 전기 이월 원가와 해당 사업연도 전체 매수액·수량으로 계산한다. 연중 조회에도 이후 입력된 같은 사업연도의 매수가 영향을 줄 수 있는 기존 원칙을 유지한다. **이후 매수가 남아 있는 중간 전량 매도에 연말 최종 처분의 잔여액 규칙을 적용하지 않는다.** 마지막 매수 이후 종목 잔량을 모두 처분할 때 남은 확정 세무원가를 제거한다.

이동평균법은 이후 재매수가 있더라도 전량 처분 시 남은 확정 원가를 정리한다. 취득·처분 과정의 정밀 원가를 별도로 추적하여 부분 처분 때 생긴 반올림 잔액으로 평균단가가 흔들리지 않게 한다. 다음 사업연도의 세무 평균 계산은 전기에서 확정해 이월한 원가를 기준으로 시작한다. 회계 장부의 제거와 종목 세무원가 배분은 별도 계산하며 혼합 분류의 배분효과도 보존한다.

## 4. 적용 시작 연도와 과거 자료 보존

데이터 관리 화면의 **금액 정밀도 · 원 단위 반올림**에서 적용 시작 사업연도를 선택한다. 사업연도는 종료연도 기준이며 3월 결산도 같은 규칙을 따른다. 정책은 `roundingPolicy` 설정과 변경 감사 로그에 저장된다.

- 새 빈 작업공간은 생성 시점의 연도부터 원 단위 기준을 기본으로 둔다.
- 정책이 없는 기존 DB·브라우저 자료·JSON 백업은 기존 `LEGACY_CENT_V1` 계산을 유지한다. 화면의 새 기본값을 과거 자료에 몰래 주입하지 않는다.
- 적용 연도 전의 계산·정답표는 기존 0.01원 기준이다. 기존 FVOCI 정답표의 소수 금액을 일괄 수정하지 않는다.
- 확정 연도에 영향을 주는 정책 추가·변경·삭제는 차단한다. 미래 연도 정책을 추가해도 과거 결산 스냅샷·승인·원장을 재작성하지 않는다.
- 전기에 소수 잔액이 남아 있다면 원 단위 전환 대사가 필요하다는 오류로 중단한다. 임의 손익·기타·유보 행으로 차이를 메우는 자동 전환은 제공하지 않는다.
- 정책 변경으로 원천 버전이 바뀌면 미확정 검증표·검증·승인을 재검토한다. 기존 승인이 있으면 취소·역분개 후 새 회차로 검토한다.

신규 DB 계산 실행은 `rational-won-v1`과 `KRW_WON_V1`을 기록한다. 프로필 정의는 최초 원 단위 계산 때 `rounding_profiles`에 추가하고 이후 변경하지 않는다. 스키마 v2의 테이블 구조 변경이나 기존 데이터 마이그레이션은 필요하지 않다.

## 5. JavaScript·Python 검증

거래·평가 입력 화면에서도 수량 × 단가를 십진 곱셈으로 계산한 뒤 반올림한다. 원문 단가와 반올림 전 `rawAmount`·`rawFairValue`는 개별 증빙에 보존한다. 예를 들어 `3 × 0.16666666666666666 = 0.49999999999999998`은 0원이며, 부동소수점 곱셈 결과 0.5를 만들어 1원으로 바꾸지 않는다.

JavaScript는 십진 입력을 BigInt 분수로 파싱하고 평균·비례배분·반올림까지 정확한 정수 연산을 사용한다. Number.EPSILON으로 금액에 보정치를 더하지 않는다. Python은 Decimal로 입력을 해석하고 Fraction으로 평균·비례배분을 유지한다. 두 엔진은 서로의 계산 코드를 실행하지 않는다.

화면에 정수 원을 넘길 때는 JavaScript가 정확하게 표현하는 정수 범위를 검사한다. 표현할 수 없는 금액을 근삿값으로 조용히 반환하지 않는다. 입력 숫자 자체가 외부에서 이미 정밀도를 잃었다면 복구할 수 없으므로, 긴 소수 입력은 십진 문자열로 보존하는 것이 기준이다.

검증 자료는 `tests/fixtures/won_rounding.json`, `test_won_rounding.py`, `test_won_rounding.js`에 있다. 고정 처분 정답·음수 절반·큰 금액·작은 잔액, 200개 경로의 거래별 손익·OCI·유보·기말 잔액·배분효과, 12월·3월 결산, 정책 전환·확정 보존, 승인·취소·재승인·원장·결산, 소수 조정 행 차단과 저장 실패 화면을 확인한다.

```bash
python3 -m unittest discover -s tests/python -t . -v
node tests/js/test_won_rounding.js
```

기존 독립 FVTPL 검산기와 소수 단위 정답은 과거 기준의 회귀 검증으로 보존한다. 원 단위 정답과 별도로 읽는다. 법정 신고서 제출 단위, 거래비용·이연법인세·특수 거래의 별도 처리까지 검증한 것은 아니다.
