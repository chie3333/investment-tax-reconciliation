## 현재 저장·실행 기준

- `python3 -m app.server`로 실행한다. 기본 파일 `data/investment.sqlite3`가 없으면 정규화 DB를 생성하고 앱을 연결한다.
- 신규 DB에서는 종목·자산·거래·평가·정책을 개별 테이블에서 읽고 저장한다. 전체 원천을 `workspace.payload`에 다시 저장하지 않는다.
- 계산 실행·승인·결산의 JSON은 당시 입력·판단·잔액을 보존하는 고정 근거다. 추가 설정과 개별 입력의 증빙 JSON도 유지한다.
- 기존 JSON DB가 이미 있으면 기존 저장 경로를 사용한다. 자동 이전·삭제·과거 결산 재작성은 하지 않는다.
- 현재는 단일 사용자·한 회사의 로컬 작업공간이다. 확정 연도의 수정·승인 취소는 차단한다.
- 새 작업공간은 원 단위 계산을 기본으로 한다. 기존 자료는 적용 시작 사업연도 전까지 0.01원 기준을 보존한다. 법정 신고서 출력·절사 단위는 별도 확인 사항이다.

## 검토 화면 개편 — 2026-10-27

[검토 화면](REVIEW_WORKSPACE.md)의 4단계 배치, 표 조정 행 편집, 종목·승인 상태·금액 계산 과정, 승인 원문 읽기 전용 표시, 원장 차이 분류를 구현했다. 승인 요청 중 화면 전환·중복 클릭·후속 조회, 검증 실행별 처리 폼의 비동기 전환 회귀 테스트를 추가했다. 조정 원인 검증은 두 DB 경로에서 공통 함수를 사용하며 기존 결산·사용자 자료를 재작성하지 않는다.

## 검증 결과

이 기준 구현에서 Python 테스트 **110개**, JavaScript 테스트 파일 **12개**가 통과했다. 신규 DB 연결 테스트는 정답 사례 16개 × 두 정책의 저장·조회·승인·원장·결산, 취소·재승인, 저장 충돌과 실패 시 전체 취소, 연도별 정책과 확정 보존, 3월 결산 이월, 검증·이슈 이력을 포함한다. 테스트 자료는 임시 DB에만 입력했고 실제 앱에서는 빈 원천 상태의 연결 표시를 확인했다.

테스트 통과 범위는 실제 KRX 인증 환경, 모든 화면 조작, 모든 법령 예외와 신고 결과 전체를 포함하지 않는다. 각 정답표의 적용범위를 함께 확인한다.
