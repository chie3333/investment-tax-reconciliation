# 서버 독립 재계산과 승인·결산 연결

상태: **구현 완료 — 신규 정규화 DB 연결 및 기존 DB 호환 포함** · 기준일: 2026-10-26. [완료 현황](IMPLEMENTATION_STATUS.md)을 함께 본다.

## 달라진 점

서버는 SQLite에 저장된 원천 거래·평가·회계분류·회사 정책으로 금액을 직접 계산한다. 브라우저가 보낸 금액은 비교 대상이며 승인·결산의 기준값은 서버 계산이다. 적용 가정은 [FVOCI 정답표](FVOCI_ANSWER_CASES.md)와 같다.

```text
저장된 거래·평가·정책 + 원천 버전
                 ↓
서버 독립 재계산
                 ↓
브라우저 금액 비교 → 다르면 오류
                 ↓
서버 계산 근거가 붙은 검증표
                 ↓
담당자 검토 → 승인 직전 재계산·자산별 유보 증감 대사
                 ↓
승인한 금액만 유보원장 전기
                 ↓
결산 직전 재계산 → 검증 이력·검증표·승인·원장·기말 장부 대사
                 ↓
결산 확정 및 계산 근거 보존
```

## 계산하는 내용

- FVTPL·FVOCI 지분상품의 매수·매도·평가·배당
- 종목 통합 세무원가, 사업연도별 총평균법·이동평균법
- 비12월 결산과 사업연도 경계에서의 방법 전환
- 회계장부, 세무원가, 과세손익 후보, 장부 차이 증감
- 처분한 주식의 OCI와 잔여 보유분의 OCI 구분
- 누적 OCI 이익잉여금 대체 / OCI 유지 정책
- 거래별 자산 간 원가 배분효과와 기말 배분잔액

`app/server/calculation.py`가 독립 계산을 담당한다. JavaScript를 실행하거나 브라우저 계산 함수를 복사해 호출하지 않는다. 입력 금액은 Decimal로 해석하고, 반복 비례배분은 정확한 유리수로 유지하여 반올림 경계의 누적 오차를 피한다. 금액을 내보낼 때 소수 둘째 자리까지 반올림하며, 정확히 절반이면 부호와 관계없이 절댓값이 큰 쪽으로 반올림한다. 예: 1.005 → 1.01, -1.005 → -1.01. 종목 원가 배분의 잔여액은 마지막 **보유 자산**에 배분한다.

위 소수 둘째 자리 규칙은 **정책이 없는 기존 자료의 LEGACY 기준**이다. 신규 원 단위 정책은 평균·비례배분 정밀도를 유지하고 거래별 금액을 정수 원으로 확정하며 마지막 처분에 잔여액을 반영한다. JavaScript도 BigInt 분수로 계산한다. 적용 연도·전환 제한·정답은 [원 단위 처리 기준](ROUNDING_POLICY.md)을 따른다. 법정 신고서별 절사 단위는 별도 확인한다.

## 각 단계의 확인 사항

| 단계 | 서버에서 확인하는 내용 | 실패하면 |
|---|---|---|
| 자동 검증 | 저장된 원천 버전, 서버 수량·장부·세무원가와 브라우저 결과 | 오류 이력 저장, 해당 검증 이력으로 결산 불가 |
| 검증표 생성 | 원천 전체를 재계산하고 후보의 금액·원천·범위를 비교 | 검증표 생성 안 됨 |
| 검증표 승인 | 원천 버전, 계산 버전·결과 식별값, 후보금액, OCI 정책, 자산별 유보 증감 합계 | 승인·원장 전기 모두 취소 |
| 결산 확정 | 현재 검증 이력, 새 서버 계산, 모든 필수 검증표, 승인 전기, 브라우저 기말 수량·장부·원가, 자산별 기말 유보, 종목 통합원가 | 결산 미확정 상태 유지 |
| 차기 사업연도 | 직전 확정 기말 유보와 서버가 원천에서 재계산한 기초 장부 차이 | 차이가 있으면 오류 및 결산 차단 |

금액 비교는 소수 둘째 자리로 산출된 서버 금액과 일치해야 한다. 경고 확인 체크박스로 금액 불일치 오류를 넘길 수 없다. 검증표 승인·검증 실행·결산 확정은 각각 같은 DB 트랜잭션 안에서 원천 버전을 읽고 처리하므로, 중간에 다른 저장이 끼어들어 계산 근거와 원천 버전이 엇갈리지 않는다.

검증표와 승인 JSON에는 계산 엔진 버전·결과 식별값·기준일·원천 버전이 기록된다. 결산 이벤트에는 같은 근거와 서버 기말 장부금액이 남는다. 결과 식별값은 결과를 비교하기 위한 해시이며 사용자 인증이나 감사 로그 변조 방지를 제공하는 전자서명은 아니다.

## 혼합 보유의 배분효과

동일 종목을 FVOCI 10주 100원, FVTPL 10주 300원에 매수하면 종목 전체 원가는 400원이고 각 자산에 200원씩 배분한다. 두 번째 매수 시 FVOCI 자산의 장부 차이는 +100원, FVTPL 자산의 장부 차이는 -100원 바뀐다.

따라서 매도·평가뿐 아니라 **장부 차이 배분효과가 있는 매수**도 검증표 생성 대상에 포함한다. 검증표는 자산별 배분효과를 보여 주며 첫 조정 행은 대상 자산을 선택할 수 있다. 추가 JSON 행은 `asset_id`로 대상 자산을 지정한다. 서버는 자산별 승인 유보 증감 합계를 재계산 결과와 비교한다.

초기 구현의 `과세소득 후보 − 유보 증감 = 기타`라는 일반 잔액 공식은 후속 [2026 복수 행 규칙](TAX_ADJUSTMENT_RULES_2026.md)에서 자동 제안 용도로 제거했다. 확인된 범위의 일반 평가·처분만 원인별 행을 제안하며 혼합 보유는 법적 행 구성을 별도로 검토한다. 수동 검토 경로에서도 자산별 유보와 과세소득 합계·방향을 대사한다. 다른 법적 처리가 필요한 사례라면 숫자를 억지로 맞춰 승인하지 않고 적용 모델과 원천 가정부터 검토해야 한다.

## 기존 미확정 검증표의 근거 갱신 방법

아래 절차는 같은 DB에서 검증표 근거를 갱신하는 방법이다. 기존 JSON DB를 정규화 DB로 자동 이전하는 절차는 아니다.

1. 기존 SQLite와 내보낸 JSON을 백업한다.
2. 대상 사업연도로 자동 검증을 다시 실행한다.
3. 검증표를 재생성한다. 이전 원천 버전 또는 서버 계산 근거가 없는 초안은 `SUPERSEDED` 이력으로 보존하고 새 초안을 만든다.
4. 기존 승인에 서버 계산 근거 또는 현재 조정 규칙 근거가 없다면 미확정 연도에 한하여 승인 취소 → 역분개 → 검증표 재생성 → 재승인한다. 기존 승인 행과 원장 이력은 삭제하지 않는다. 확정 연도는 이 절차로 자동 재개방하지 않는다.
5. 브라우저·서버 차이가 있다면 원천 거래·정책·LOT 배분을 확인한다. 잘못된 보유수량, 중복 ID, 누락된 필수 금액 등은 서버 계산 단계에서 차단된다.
6. 자산별 원장 대사까지 완료한 뒤 결산을 확정한다.

이미 확정된 과거 결산을 자동 변경하거나 재개방하지 않는다. 결산 재개방 기능은 별도 후속 작업이다. 새 DB 위치나 강제 데이터 마이그레이션도 필요하지 않다.

## 현재 DB 저장 경로

신규 정규화 DB에서는 `app/database/repository.py`가 SQL 원천을 계산 입력으로 조립하고 `services.py`가 검증·승인·원장·결산을 처리한다. `calculation_runs`와 자산 잔액·종목 원가 풀은 고정 근거로 저장하며, 동일한 회사·연도·원천 버전·입력·결과의 계산은 재사용한다. 검증 실행은 매번 별도 이력으로 추가한다.

조정 행은 승인 요청 때 `tax_adjustment_rows`에 기록하고 승인 결정의 행 스냅샷과 함께 고정한다. 결산 때 실제 조정 행·전기 행을 승인 근거와 다시 비교한다. 기존 JSON DB는 기존 서버 서비스가 처리하며 파일 구조를 자동 변경하지 않는다. [DB 안내](DATABASE_SETUP.md)를 참고한다.

## 테스트 범위

후속 [FVOCI 유보 환입 독립 검산](FVOCI_RESERVE_RECONCILIATION.md)은 앱 계산을 호출하지 않는 검산기의 금액으로 승인 입력을 구성하고, 8개 사례·두 OCI 정책에서 거래별 전기와 20개 사업연도 결산을 대사한다. 기말합계가 같은 거래별 전기 오류와 부분 처분 취소·재승인도 검증한다.

```bash
python3 -m unittest discover -s tests/python -t . -v
node tests/js/test_fvoci_answers.js
```

- 손계산 정답표 6개 사례와 OCI 두 정책, 24개 중간·최종 결과
- 같은 입력에 대한 브라우저·서버의 거래별 금액·기말 장부·배분효과 비교
- 고정 난수로 만든 혼합 보유 48개 경로 및 반 센트 반올림 경계
- 누락·중복·변조한 후보, 브라우저 금액 불일치, 오래된 원천 버전
- 잘못된 승인 유보 증감 및 다른 자산으로 잘못 배분한 행
- 서버 근거가 없는 기존 검증·승인, 원장 전기 변조
- 승인 취소·재생성·재승인, 혼합 보유의 매수 배분, 두 사업연도 유보 이월
- HTTP 처리 경로의 생성 → 검증 → 승인 → 결산 성공·차단
- 신규 정규화 DB의 정답 16개 × 두 OCI 정책 HTTP 경로, SQL 원천 왕복 저장, 취소·재승인·확정 보존·3월 결산 이월 (`test_database_app.py`)

FVOCI 표시 정책은 후속 [사업연도별 정책 관리](FVOCI_POLICY_YEARS.md)에서 연도별 적용과 확정 결산 보존·이월을 구현했다. 실제 세법 예외, 채무상품, 거래비용, 이연법인세, 독립적인 자본 재분류와 법정 신고 출력은 이 작업의 계산 범위 밖이다.


## 검토 화면 연결 보완 (2026-10-27)

새 검증표 후보 JSON에 설명용 `review_detail`을 기록하고 승인 행의 `label`(조정 원인, 최대 200자)을 보존한다. 계산 엔진 식별값·승인 재계산·원장 전기·확정 대사는 그대로 사용하며 스키마 변경은 없다. 설명 정보는 승인 권한의 근거가 아니며 기존 승인·확정 스냅샷에는 소급 추가하지 않는다. 두 DB 경로가 같은 조정 원인 정규화 규칙을 사용한다. [검토 화면 안내](REVIEW_WORKSPACE.md)를 참고한다.
